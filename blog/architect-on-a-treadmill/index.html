跑步机上的架构师：当 Claude 崩溃那一刻，我心慌出汗

求索手记 2026-04-14 AI Claude Code 方法论 自省

阅读时间：约 5 分钟 · 2250 字

前阵子某个深夜我在电脑前做一些收尾，打开 Terminal 想 commit 一个文件——Claude Code 弹了一个 500。

我盯着屏幕看了三秒，然后发现自己心跳在加快，手心冒汗。

那一刻我想的不是"API 可能宕机了"，也不是"换个 model 试试"。我想的是——如果这东西今晚一直挂，我明天怎么办？

这个念头让我意识到比那个 500 更重的事：我已经不是在用 Claude，是在被 Claude 持有。

深度用它大概两个月了。两个月前我觉得它是工具。现在我做梦都在改 prompt。每天坐到电脑前打开的第一个窗口是 Claude Code。写作、写论文、写 skill、写邮件——我甚至已经开始忘记"没有 AI 的时候我是怎么写东西的"。

一、这不是我一个人的事

你可能会说：这是你自己的问题，是你的工具焦虑。

我一开始也这么想。然后我去观察我的学生。

他们打开电脑要写一份课程作业——第一个动作是打开 ChatGPT。不是打开 Word 先列个提纲，不是打开文献先看一眼，是直接开 AI 然后问"帮我写一篇 1500 字的讨论 XXX"。

这不是他们堕落，是他们更诚实。他们只是承认了一件我这代人还在假装没发生的事——认知基础设施已经和电网、自来水并列。

电力断了你慌不慌？自来水断了你慌不慌？那我 Claude 崩了心慌出汗，说是个人意志不坚定，好像也说不过去。

当然，我心智模型里有一条写得很清楚——独立思考是逃逸速度。挑战者的声音立刻跳出来：你这不就是用"时代病"给自己开脱吗？

我承认这话刺耳。但我想说的不是"所以依赖是对的"。我想说的是——依赖是默认值，觉知才是修行。挑战者防的是"用时代病当遮羞布"；但反过来，如果坚持"我要完全独立"，那就是另一种自欺——拒绝承认基础设施已经换了。

心慌出汗不是弱点。那是我的身体比脑子先意识到：游戏规则换了。

二、我搭了一座山，自己迷路了

这段时间我陆续给 Claude Code 搭了一些 skill。

规划检索的、拟大纲的、管理知识库的、生图的……什么顺手就搭一个。我甚至专门搭了一个让它"每次打开新窗口自动恢复上下文"的 skill。

可笑的是，我经常记不住自己都搭了什么。

有时候要用某个功能，我得回 ~/.claude/skills/ 去 ls 一下，翻一圈，才想起——对，这个我搭过。然后还要再 cat skill.md 重新熟悉自己的产品。

这就是视频里说的诱发需求。Email 本该减少开会，结果变成 CC 五个人 BCC 三个。手机本该解放办公室，结果把我们绑在屏幕上 24 小时。AI 本该把我从中间层工作中释放出来——结果我现在把管理这些 skill 本身变成了新的中间层工作。

工具越多，服务工具的时间就越多。我以为自己在做减法——让 AI 接手重复劳动——结果做的是高级的加法：把原本不存在的工具维护成本重新引入自己的生活。

三、跑步机上的架构师

但事情没那么简单。

如果你问我，是不是该删掉这些 skill、回到"手动写论文"的状态——我会立刻说不。因为我不是在单纯地用 Claude 写论文，我在设计"如何用 Claude 写论文"。这是两件事。

Joe 张国洋的视频把人分成三层：上游（战略/商业目的/客户判断）、中间层（写报告做简报）、下游（执行交付）。他说大多数人拿到 AI 后不往上下游走，而是用 AI 在中间层跑更快。

但我的位置是第三种——我搭那个"让自己在中间层跑更快"的架构本身。

这算上游吗？

纵深的声音说：算。你从"科研工作者"进化成了"科研工作流的架构师"。福特造车是中间层，设计流水线的人是上游，定义"制造业可以流水线化"的人是元上游。你正在做的是第三件事。代价是残酷的——架构师的产出不在本季度 KPI 里。你设计一个 skill 不会马上换来一篇可见的成果，但它会在未来很长一段时间里以复利方式吃掉别人反复付出的时间成本。

挑战的声音说：扯淡。搭 skill 是为了更快写论文，论文写作本身就是中间层。把中间层外包给工具，然后在"工具设计"的中间层跑——层级没换，位置换了。这叫元中间层，不叫战略层。真正的上游是三个问题：这个 idea 值不值得做？这个领域三年后往哪走？我这辈子要不要在工程管理赛道上押注？——这些问题，我搭再多 skill 也回答不了。

两个声音我听了一晚上。我没法裁决谁对。

但我想清楚了一件事：搭 skill 可以是元上游，也可以是元中间层——分野在于你先问了什么问题。

先问"这个 idea 值不值得做"再搭 skill = 元上游；不问就直接搭 = 把战略焦虑偷偷换成了工程审美。

想"这个 idea 要不要做"很痛，因为会错。设计一个 skill 不会错，只会"不够优雅"。架构师的快感之所以上瘾，恰恰因为它比面对真上游问题轻松。

四、没东西想说的人

然后我想起我一开始用 Claude Code 写论文时的一件事。

我把流程越调越精细，越做越像一条自动化的生产线。但不管调多精细，它最后还是给不出一份完整的好东西。最后那一里路，依然是我自己去跟它深入交流，去重构段落逻辑，去决定某段到底该说什么。

视频里 Joe 说这是判断力——区分 80 分和 60 分的能力。他说这是 AI 时代的稀缺资源。

但我想更进一步。

判断力这件事会被 AI 追上。Opus 4.6 比 3.5 已经好了很多。当 AI 读过几百万份审稿意见、几十万轮修改前后对比，它的"品味"会超过任何单个审稿人——不是因为它更聪明，是因为它的样本量是我的一万倍。

我今天的判断力不是护城河，是时差。

真正不会被追上的，是我想说什么。

AI 可以生成 100 个逻辑自洽的版本，但"这篇论文应该说什么"——这不是能力问题，是主体性问题。即使 AGI 来了，"Zylen 想说什么"依然只有 Zylen 能决定。因为那是从我的生命经验、审美偏执、未解的困惑里长出来的。

所以未来学者会分化。一类是没东西想说、只用 AI 凑字数的——他们是 AI 的寄生物，产出边际价值趋近于零。另一类是有自己非说不可的话、用 AI 放大它的——他们是 AI 的主人。

稀缺的不是"会用 AI 的人"，是有东西可以让 AI 放大的人。

结尾：在觉知里上瘾

说回那个深夜。

Claude 的 500 最后没挂太久，大概十分钟就恢复了。我接着 commit 完，洗澡，睡觉。第二天醒来，我依然打开电脑继续写。

我不会戒 Claude。也不会假装自己"心慌出汗"是矫情。

我只想记住一件事——热爱不是无毒的圣物，是我睁着眼睛承受自己中毒的能力。

陀飞轮里林夕唱过：

全力地發亮，卻任由霉菌滋長，人愈大愈容易這樣。

人们以为热爱是纯粹的、不伤身的。但真正深入的投入永远是带痛的。区别不在痛不痛，在有没有觉知。

上瘾是闭着眼睛冲进去，心慌了就再灌一勺刺激盖住它。 热爱是睁着眼睛冲进去，心慌了停下来问一句——我现在为什么在这里。

所以从今晚开始我要做一件事：每完成一个东西，问自己——这件事让我更靠近上游（idea/方向）还是下游（影响/连接）？ 如果答案是"哪里都没靠近"，那我今天赢来的，就只是忙碌的安全感。

我依然会在 Claude 里做梦。但我希望梦里偶尔能有一瞬间的清醒——不是为了逃离这个依赖，是为了在依赖里保持不迷路。

依赖是默认的，觉知是修行。
